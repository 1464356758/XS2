# 个人端、代发端和总检查

管理工作台版本 1.4.0，写作内核仍为 4.3-quality。网页入口 index.html，代发入口 reader.html，原阅读器 legacy.html。

## 数据与隐私

管理仓库使用根目录 books.json。由个人端维护小说编号、实际 book_id、仓库链接、分支、检查开关、北京时间计划时刻、宽限时间和起算日期。清单经过字段白名单处理，保存可选chat_url、feedback_url及settings.reader_url；不包含凭证或旧费用数据。GPT链接随清单同步，公开仓库中可被读取。feedback_url只登记实际任务反馈对话，不配置投递；打开时优先使用它，否则使用工作聊天chat_url。

GitHub写入凭证默认保留在当前窗口sessionStorage；只有用户主动勾选记住时才写本浏览器localStorage；启用网站通道时经本站服务器临时转发，不落库、不写日志。它只进入所配置管理仓库的 GitHub API 请求，不进入 raw 下载请求、其他小说请求、数据草稿、备份或报告。请求禁止重定向；小说正文和Git版本发现不转发用户凭证；显式授权的管理仓库API请求可使用本次凭证。

代发码 NX1 编码仓库定位信息和作品身份，带误复制校验。它不是加密访问控制，不能撤销对公开正文的访问权限。合作人不用任何写入凭证。

新版个人端的简化交互和自动保存见《工作台1.1交互与同步.md》。费用页面已移除。

个人端记住本机最后核验通过的阅读章号；刷新目录后续读，按仓库、实际分支和book_id隔离。整本导出读取同一提交，任何一章核验失败就不产生部分成功文件；同书防止重复启动，切书或刷新取消旧导出。代发端复制前固定章号、正文与哈希，异步复制时切章不会记错。已复制章节版本变化时重新建议该章并提示复核；复制进度只在本浏览器，不证明平台发布或跨设备同步。两端按所读state展示对应章号及正文哈希的既有发布登记；没有登记只说“尚未登记”，不推断平台未发布，版本不符则提示核实。网页不自动写发布回执。

## 一致性和网络开销

正常公开读取通过 Git smart-HTTP 版本发现取得真实 HEAD 或指定分支，再从该不可变提交读取索引、state 或正文。不会把不同分支头的状态拼成一个结果。

当前Sites网页通过同站/api/github连接GitHub。公开正文使用按提交号定位的 raw 下载，今日查询读取最新章节文件历史。正常公开读取路径不调用REST接口；读取失败如实显示，不以“正在使用备用通道”冒充完成。查询由作者主动触发，最多三本并行。网络服务仍可能断连或拒绝请求。

保存清单前重新读取，比较原清单文件哈希。允许报告文件单独更新，但拒绝覆盖别人改过的清单。个人端单文件清单使用Contents PUT与文件SHA比较更新，保留其他文件，最后读取新提交的实际文件核对；总检查的多文件报告仍保留base tree、单父提交和非强制推进。网络中断导致结果不明时，先重新读取，不盲目重试。

## 网页今日查询

勾选小说后点击“查询今天更新”，立即检查所有已勾选小说，按北京时间的最新章节文件提交日期判断，不需要日报、计划到点或完成回执。最近7天观察可随清单自动保存；具体规则与可选定时查询入口见《今日更新查询.md》。

## 独立的严格采用证据核验（旧工具）

以下工具与状态仅供单独核对采用证据，不再决定网页“今天更新”状态。

管理仓库只保存数据。核验程序位于通用系统母版 https://github.com/1464356758/xiaishuo-ZUOZONG 。在临时目录按同一固定提交取得 tools/check_updates.mjs、web/dist/hub-core.mjs、web/dist/core.mjs、web/dist/query-model.mjs 和 web/dist/github-transport.mjs，保持相对目录后执行。不要假定仅上传管理初始化包就会有这些程序。

具备直接网络和临时环境凭证时可以运行：

```bash
node tools/check_updates.mjs --management https://github.com/作者/管理仓库 --branch main --output /tmp/novel-report.json
```

默认只核验并输出，不写远端。直接写回需要环境变量 NOVEL_HUB_GITHUB_TOKEN，只授权管理仓库，并显式添加 --write。不把凭证写入文件、命令参数或公开仓库。

```bash
node tools/check_updates.mjs --management https://github.com/作者/管理仓库 --branch main --write
```

每次都重新读取名单，不写死十本。写回前再次确认清单没变化，避免覆盖更晚的报告。报告、快照和 latest 在同一个提交里更新，历史文件使用日期和运行编号保存。

## 仅有 GitHub 连接器时

如果执行环境无法直接访问 GitHub 网络，不绕过环境策略。通过已授权连接器读取管理仓库真实提交、books.json 原文和上次报告，再逐书按固定提交读取下面文件，写到临时 connector-input.json：

```json
{
  "type": "novel-hub-connector-input-v1",
  "management_repository": "https://github.com/作者/管理仓库",
  "management_branch": "main",
  "management_commit": "替换成实际读取到的40位提交号",
  "registry_text": "完整的books.json原文字符串",
  "previous_report": null,
  "books": {}
}
```

books 用清单的 entry.id 作为键，每项包含 repository_url、branch、commit、committed_at 和 files。files 按仓库路径索引：实际读取文件用 {"text":"完整UTF-8原文"}，已确认该提交下404的文件才用 {"missing":true}。未读取不是不存在。

每书至少收集 online/index.json 和 book/state.json。根据当天回执是否存在，继续收集 book/daily/北京时间日期.json、book/daily/active.json，以及回执引用的正文、章后记录和 release 报告。所有内容来自同一实际提交，保留原文，不重排 JSON 再冒充原哈希。

```bash
node tools/check_updates.mjs --input /tmp/connector-input.json --output /tmp/novel-report.json --bundle /tmp/write-bundle.json
```

程序缺少证据时会给出待核实，不补造文件。bundle 包含精确输出文件及 guard：books_sha256、清单版本、开始读取的提交。用 GitHub 工具写回之前重新读取当前清单，核对 guard；读取当前提交的真实 base tree，建立父提交并非强制更新。若存在更晚报告或版本冲突，停止并重新核验，不能强行覆盖。

bundle 只是待写文件，不是远端完成证明。写入后至少回读 books.json、reports/latest.json、本次日期报告，核对范围、实际内容和哈希，成功才报告已写回。

## 严格核验的状态含义

- 已更新：核验本日新采用正文、实际采用日期、冻结记录、章后记录和通过报告。
- 未更新：已到期限，能正常读取，未找到本日有效完成回执。
- 未完成：有尚在运行或已中断目标；先核实再恢复。
- 尚未到期：未到起算日期或计划完成宽限。
- 待核实：网络、身份、证据缺失、旧格式或校验问题，不能断言成功或失败。
- 不参与检查：当前清单未勾选，不计为漏更。

这些状态属于旧严格核验工具。网页1.2的状态、查询时效与保存规则见《今日更新查询.md》。两者均不证明文学质量或平台发布。

新账号的计划数量、会员额度、后台工具权限和中国大陆实际网络必须实测。本版本没有自动创建 ChatGPT 计划或跨聊天发送消息的接口。使用设置指令在对应聊天真实建立计划。

## 多书与章节搜索

工作台1.4可在首页、日更选书、阅读选书、代发选书和查询结果中按书名或仓库关键词筛选。多个关键词用空格分隔，均须匹配；英文忽略大小写，兼容全角字母、数字和空格。各入口查询独立，不写入books.json。

搜索只改变显示，不改变enabled勾选、定时任务或今日更新范围。没有匹配书时展示空结果，不能静默生成另一部书的指令或代发码；清除后恢复列表与原先选择。读书和代发复制仍以实际打开并核验的正文为准。

个人端和代发端都可按章号或标题筛选正式目录。纯数字精确定位章号，例如22、022、第22章均定位第22章；标题可用多个词。筛选目录不会重新下载全部正文。清除恢复全部目录，只有点击具体章节才加载该章。查询结果的“导出全部结果”始终包含该次完整查询。
