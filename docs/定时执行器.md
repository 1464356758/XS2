# 定时写作执行协议 1.0

GPT负责读原文、写作和实质审核；GitHub Actions只运行Python文件工具、验证版本并保存。个人端和代发端继续读GitHub，不需要GPT API Key，不自动投稿。执行器不替模型填写pass，也不证明文学质量。

## 固定入口

- `.github/workflows/novel-executor.yml`：监听默认分支的`.automation/request.json`变化，同一本书串行执行，不取消正在运行的批次。
- `tools/task_executor.py`：运行既有V4.3工具。每批在隔离副本执行，保护全部旧章与事实记录；状态变化后自动重建并验证索引。finalize全部通过后才保存新采用章和完成回执，失败不会留下没有回执的半次采用。
- `.automation/config.json`：本书book_id与唯一automation_id。初始化包内均为空；实际建立或复用任务后，按真实返回值登记，不复制其他书的任务编号。
- `.automation/results/<request_id>.json`：本批结果、来源提交、控制者、完整输出文件的位置与SHA。每个请求编号只用一次。
- `.automation/work/<request_id>/`：工具完整stdout/stderr，不截断后冒充已读；context写入drafts的全文资料还要由GPT实际读取。

工作流用仓库自带GITHUB_TOKEN保存结果。GitHub文档说明，该token推送通常不再触发另一轮push工作流，因此**必须检查本次executor作业及实际结果文件，不能等另一个CI自动替它完成**。来源：[GitHub触发工作流文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)。提交用原事件头检查和非强制push；并发更新就停止，不强推。

## GPT每次怎样执行

1. 读本书实际默认分支、HEAD、AGENTS、state/workflow、实际设定与路线、daily记录和本规程。每次仍实读上章、最近三章全文及到期回看范围。核对book_id、冻结和最多三轮返修。
2. 私下peek已登记的唯一任务。生成本轮独立`session_id`；从实际运行记录读取当前`platform_run_id`，取不到就填null并标明不可核实，不能编造。一次执行的后续批次沿用同一个controller。session_id是客户端生成编号，不冒充平台编号。
3. 使用GitHub工具在当前HEAD的base tree上原子提交请求及必要drafts资料；请求`base_sha`填这次提交的直接父SHA。提交只有一个父，expected_sha填当前头，force=false。请求提交不得直接改book/state、正式正文、事实记录或系统源码。
4. 读取对应source SHA的Actions记录，等本批终态。回读该请求的result，核对source_sha、book_id、request_id、controller和executor_status。普通tools_completed只是工具批次成功，仍须继续写作；只有chapter_completed且正式文件/回执回读成立才算新章保存。
5. 没取到结果，先查请求提交、作业和已有result，不重新begin或换请求重放同一操作。下一批必须重新读最新远端HEAD；不要预先排队多个请求，防止旧基线冲突。当前任务没有本地网络或Python也可通过这条固定远端路径执行，不必先用git clone，也不使用需要交互上传的中转流程。

首次配置后先发preflight，检查真实文件、冻结和索引，不生成run_id、不写小说。通过后才由真实日更执行begin。每个阶段均回读以后继续，不以“已触发”“作业成功”代替小说采用。

## 请求格式

以下是结构示例，所有占位值由GPT依据本次真实读取填写，作者无需手填JSON。请求与草稿一起提交；凭据不进入任何文件。

```json
{
  "schema_version": 1,
  "request_id": "本批独立编号_至少8位",
  "base_sha": "当前默认分支真实40位HEAD",
  "book_id": "当前state的实际身份",
  "controller": {
    "kind": "automation",
    "automation_id": "已有唯一任务的实际ID",
    "session_id": "本轮生成并持续复用的独立编号",
    "platform_run_id": null
  },
  "phase": "begin"
}
```

维护验收的preflight可用`controller={"kind":"maintenance","session_id":"独立维护编号"}`。空母版只允许book_id=null的preflight，不会初始化小说。

| phase | 额外字段 | 实际作用 |
|---|---|---|
|preflight|无|核验文件并同步派生索引，不创建执行锁或章节|
|begin|必要时stopped_evidence|真实daily begin；返回started/continue_owned/resumed、already_completed、recovered_completion或recovery_required|
|command|run_id、commands数组（1—6条）|核对控制者，执行写前/候选/修订/审核工具，保存完整输出与索引|
|finalize|run_id、text、record、report相对路径|release-check→adopt→daily finish→workflow→索引，整体通过才落盘|
|block|run_id、reason|仅登记本轮拥有的真实阻断，保留目标、候选和次数|

commands中的对象为`{"script":"novel_state.py","args":["--root","book","brief-check","--file","drafts/CH002_brief.json"]}`。允许brief-request、brief-check、history-search、context、candidate、repair、check-record、release-request、release-check、incident；set-input只准roadmap。online_state只允许`["--project",".","task",...]`、build-index、validate-index。路径留在本仓库；--out只放drafts或.automation/work。禁止任意shell、init、publish、reopen、关闭冻结和直接adopt；采用统一走finalize。

## 控制者与恢复

begin保存controller和实际GitHub作业编号。后续command/finalize/block必须匹配该controller及run_id；另一轮不能拿旧编号直接写。当前controller重复begin返回continue_owned，不重复开章。同一轮block后可核对原错误并在原控制者下继续，修订次数不清零。

另一轮只有实际peek确认**原controller的平台运行编号已终结**，并查询确认关联执行器作业均已终结，才能提供下列证据恢复同一章：

```json
{
  "source": "automation_run_lookup",
  "automation_id": "原控制者任务ID",
  "platform_run_id": "原控制者平台运行ID",
  "run_id": "旧daily执行编号",
  "status": "completed",
  "all_executor_jobs_terminal": true,
  "observed_at": "本次实际查询的带时区时间"
}
```

执行器核对归属、目标、冻结基线并保留旧controller证据与返修历史；第三方平台终态由GPT真实查询后提供，是有来源的核验声明，不是GitHub代码自行认证了ChatGPT后台。不能拿本轮观察任务completed冒充旧执行completed，不能只因超时恢复。无归属的旧running记录或原平台编号未知时返回recovery_required，保持原记录；须回原发起处核实停止，不自动删锁或推断已停止。

## 写作与失败出口

采用原V4.3实读、任务书、场景预算、全书检索、正文反向提纲、限信息审读、八项证据检查、到期全文回看和最多三轮修订。资料准备后继续完成目标正文；不因context生成成功结束整次日更。真实独立输入才标isolated_input，同一对话用same_context_approximation。

工具失败时，已拥有的执行记录被标blocked，完整输出和未超限候选保留；finalize失败先回到该批之前的正式状态再登记blocked，不撤回此前修订次数。连接或提交失败时不能说已写回；核对后在下一次运行恢复同一目标。`running`是持久记录，不证明后台仍存活。

一次网络、工具或篇幅错误不自动停用整本每日计划。作者明确要求停止或预先授权的停用规则才改变计划；普通单次失败不调用automations.update，不改时间、不另建任务。现有固定反馈对话和日程保持，实际模型/思考档位取不到仍标未验证。

日常今日更新仍按最新正式章节文件最近提交的北京时间日期判断；不添加日报、计划到点或完成回执门槛。章节采用、GitHub保存、小说平台发布分别记录；没有真实平台依据不登记发布。工程测试与预检不证明文学质量、签约收益或多本长期无人值守。
