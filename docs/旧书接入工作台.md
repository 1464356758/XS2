# 旧书接入工作台

添加链接即可阅读兼容的正式索引；可靠的每日写作核验还要求每日工具、真实采用时间及冻结证据。

1. 固定旧书当前远端提交并备份，读取原AGENTS、state、workflow、索引和实际配置。记录真实章节、候选、修订次数和未解决检查。
2. 从通用系统母版核对合并 tools/daily_update.py 和 novel_state.py 中新采用章 adopted_at 记录及其必要依赖。不要把旧书的自有代码修改直接覆盖。已有小说不能用空初始化包整体覆盖，更不能复制母版 state、book_id、正文、选题或重置工作流。
3. 旧书已启用 serial_mode 的，保留真实冻结和叙事检查状态。未启用的，不为获取绿色更新状态自动启用、追认旧章通过或修改旧章；先按既有迁移规则由作者明确决定后续方案。
4. 已有采用章没有 adopted_at 时保持原样，不补成今天。只有新采用章节由新工具自动记录采用时间，才能产生新的可核验每日回执。
5. 用临时合成测试确认代码兼容，再将代码升级原子提交并回读；不修改实际已冻结正文和语义记录。
6. 在原小说 GPT 聊天建立真实定时任务，确认启用和下次执行时间。先验证一章，再扩大到多本。

通用系统来源：https://github.com/1464356758/xiaishuo-ZUOZONG 。系统维护与小说生产分开；升级成功不代表已经开始定时任务，也不代表任何旧章自动通过新检查。
