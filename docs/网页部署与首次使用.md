# 网页部署与首次使用

个人端是 index.html，代发端是 reader.html。部署包包含网页与可选 GitHub 网络函数，不含小说正文、写入凭证或模型 API Key。通过 HTTP/HTTPS 托管，不直接双击本地 HTML。

## 首次使用

1. 打开个人端，自动读取最终版本仓库的 books.json。其他管理仓库可在“同步设置”的折叠项中更换。
2. 在“同步设置”填写仅授权该管理仓库 Contents 读写的 GitHub 凭证，点击启用自动同步。是否在本浏览器长期记住由用户主动勾选；默认只在当前窗口保留，刷新仍可用。
3. 添加小说仓库后直接阅读正文。新增、编辑、勾选会自动保存到 GitHub，只有写入后回读一致才显示已保存。
4. 勾选需要查看的小说，点击“查询今天更新”。结果直接显示最新章数、章节提交日期和状态，不限查询时间；读取失败单列。启用自动同步后，最近7天查询记录保存在 GitHub，未授权时先保存在本机。
5. 在“小说代发码”选择已经加入的书，自动显示代发码，可复制码或代发链接。

清单、计划、可选 GPT 聊天链接和代发网址存放于 GitHub。公开仓库中的配置可公开读取，凭证始终不进入仓库或备份。没有写入授权时仍可阅读，修改会显示待授权保存。费用页面已移除。

## 部署与网络

个人端和代发端可以同站部署，也可分开部署。分开时在同步设置填写真实的 reader.html 网址，它会自动同步到清单。小说、清单和报告更新不需要重新部署；仅软件代码改动需要部署。

Sites 在线版使用同站 /api/github 连接 GitHub，手机只需访问网站。正常公开读取使用 Git smart-HTTP 取得真实提交，再读取该提交下的 raw 原文；查询更新使用同一提交下最新章节的文件历史日期。这条读取路径不依赖匿名 REST 调用。写入清单仍使用已授权的 Contents API。

Netlify 包附带 netlify/functions/github.mjs 与路由配置，使用 Git 连接或支持函数的 CLI 部署。只拖拽静态文件不会部署函数。1.2版即时查询应使用 Sites 在线版或连同函数部署的 Netlify 包；纯静态直连可能受浏览器跨域限制，不能作为即时查询的可靠部署方式。

网站函数不存储文章或凭证。授权的管理 API 请求可使用用户当次凭证，小说正文与公开 Git 版本发现不带凭证。独立代发包的函数只读。Sites 构建使用 tools/build_site_worker.py 生成单文件 Worker，沿用已有站点身份和访问权限。

## 任务与恢复

首页点击“生成日更指令”，或进入导航“日更指令”。选择已加入的小说与每天执行时间，点击“生成并复制指令”，再发送到对应 GPT 工作聊天实际创建计划。完整指令有预览，复制失败可以手动复制。填写了GPT链接时可直接打开本书聊天。原“更多 → 定时指令”仍保留，补更指令仍在更多菜单。网页填写时间不会直接创建任务。取消检查勾选后自动同步，但停止写作仍需到 GPT 暂停计划。

连接失败时保留本机草稿，检查同步状态后点击重试；不会在结果不明时自动重复写入。再次打开自动读取 GitHub，多设备修改不覆盖本机尚未保存的数据。可在设置导出、导入清单备份。

十本写作任务加总检查任务的账号数量、实际会员额度、后台权限和中国大陆运营商网络仍需实际使用验证。本软件不调用计费模型 API、不自动操纵其他 GPT 聊天或自动投稿。
