# 工作台1.2：查询今天更新

## 作者操作

1. 在“我的小说”勾选需要查询的书。
2. 点击“查询今天更新”；也可以从“今日更新”页点击同名按钮。
3. 逐本显示最新章节、章节最近提交时间和状态。任何时刻可查，不等待晚上，不需要先建立总GPT任务或生成日报。

“今天”统一使用北京时间 Asia/Shanghai。查询不受计划时间、宽限时间、起算日期影响；这些旧字段仅作为写作计划参考。取消勾选只移出查询范围，不会停止GPT写作任务。

## 判断依据

每本书先通过公开 Git 版本发现取得当前真实提交，在同一不可变提交读取 online/index.json，从正式章节目录取最后一章，再查询该章节文件的最近一次提交日期。读取目录、查询日期或身份核对失败，均单列读取失败。

|状态|含义|
|---|---|
|今天已更新|最新章节文件最近一次提交的北京时间日期是今天|
|今天未更新|成功读到最新章节文件日期，日期早于今天|
|暂无正式章节|成功读到目录，目录中没有正式章节|
|读取失败|网络、目录、作品身份或日期来源未能核实；不能当作未更新|

按照作者指定口径，同章修改后重新提交今天也算更新；只改配置、索引生成时间或报告不能算。此判断只表示章节文件更新，不证明新增字数、文学质量、冻结审查或小说平台发布。正文阅读仍核对正式目录里的文件哈希。

## 网络与额度

正常公开读取路径使用公开 Git smart-HTTP、固定提交的 raw 原文和章节文件历史 Atom 订阅，不调用 api.github.com，不依赖匿名REST每小时请求额度，也不调用任何计费模型API。写入数据仍需一次GitHub管理仓库授权，通过 Contents API 保存 books.json。

GitHub文件历史Atom订阅目前可实测读取，但并非GitHub承诺兼容的正式API，未来可能变化。所有网络链路也可能不可用。失败会标明读取失败，不伪造日期、不把失败算成未更新，也不在空日报时反复尝试受限REST接口。网站函数只允许固定仓库的 Git 发现和带40位提交号的正式章节历史地址，不允许任意URL、重定向或向公开文件请求发送凭证。

## 保存和再次打开

最近7个查询日的最后一次观察保存在 books.json.query_history，与小说名单使用同一套自动同步。每条保留查询时间、查询范围指纹、小说身份、章号、正文哈希、仓库提交、章节改动提交、改动日期及成功读取时间。不含凭证和正文；GPT链接仅由原小说配置显式保存。

没有写入授权也能查询，记录先保存在本机。启用管理仓库自动保存后可同步；只有远端写入并回读一致才显示已保存。一次查询失败可保留上次证据便于排查，但当前状态仍为读取失败。相对上次成功观察可显示新增章节或内容修改。

保存的结果清楚标注查询时刻；跨天或勾选变化后标记为历史/需要重查，不当作今天当前范围的结果。再次打开读取已保存的查询观察，点击查询会重新访问各小说仓库。每次最多三本并行，一本失败不阻塞其他书。

## 可选程序与定时查询

```bash
node tools/query_today.mjs --management https://github.com/作者/管理仓库 --branch main --output /tmp/today-result.json
```

默认只读。仅当已有正确管理仓库授权时，使用环境内的 NOVEL_HUB_GITHUB_TOKEN 与 --write 保存；凭证不放进命令参数或文件。写入使用文件SHA比较，并回读实际新提交，冲突或结果不明不自动重复写入。

程序依赖 tools/query_today.mjs，以及 web/dist/today-query.mjs、query-model.mjs、hub-core.mjs、core.mjs、github-transport.mjs，须保留相对目录。初始化包包含这些依赖。网页“复制定时查询指令”只是文本，实际定时任务必须在具备相应权限的GPT中创建；本次软件维护没有创建写作或查询任务。

旧 tools/check_updates.mjs 保留为独立的严格采用证据核验工具，不作为网页日常查询的前置条件。小说写作内核和正式小说数据没有因查询口径变动被改写。
