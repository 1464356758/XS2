# 工作台1.1：阅读、代发码和自动同步

个人端包含“我的小说、日更指令、阅读正文、小说代发码、今日更新、同步设置”六个入口，已移除费用和收益计算页面。

## 日常操作

1. 默认读取最终版本仓库根目录的 books.json；也可以在同步设置中换成自己的管理仓库。
2. 添加小说时填仓库链接，书名自动识别。添加成功直接进入正文阅读，可以选章节、复制整章、导出本章或整本。
3. 点击小说列表中的书名或“查看正文”，也可以进入阅读页。
4. 代发页列出已加入的小说。选择书名就自动显示该书代发码，不再手填小说链接或再点生成。复制按钮重新核对当前选择，避免复制前一本书的码。
5. 新增、编辑、移出、勾选，以及代发网址变更都会自动保存到 GitHub。打开软件自动读取，回到页面时也会在无未保存修改的情况下刷新；无需重新部署。

首次在“同步设置”填仅授权管理仓库 Contents 读写的 GitHub 凭证。未勾选记住时，授权保存在当前窗口的 sessionStorage，刷新可继续使用；主动勾选“在此浏览器记住授权”后才写入本浏览器 localStorage。清除授权会清除此仓库在这两个位置的凭证。凭证经同站函数临时转发给 GitHub，不进入仓库、日志、导出备份或代发码。过期授权不会阻止匿名读取公开清单，但保存需重新授权。

没有授权时可以读取小说、目录和公开清单；新增内容会明确显示“待授权保存”，不会假装已经存入 GitHub。授权后会自动处理尚未保存的修改。

## GitHub 作为管理数据源

books.json 保存小说链接、书名、作品身份、计划时间、检查勾选、可选 GPT 聊天链接和代发网址。GPT 链接现在随清单同步；填写处明确标注会写入公开仓库。实际文章仍在各小说仓库。1.2版最近7天查询观察保存在 books.json.query_history，不再要求先生成 reports/latest.json；旧严格核验报告仍可保留在 reports/ 下。本机缓存只是断网时保留未同步修改，GitHub 是正式数据源。

旧版本的本机清单会尝试与远端合并。同一作品仅条目编号或接入基线不同会去重；双方同时改了同一条记录的不同版本时停止自动覆盖，可导出备份后选择版本。旧备份可导入，但旧费用记录不会导入新清单或上传到公开仓库。

自动保存合并短时间内的连续修改，始终最多一笔写入。保存过程中继续编辑会排在下一笔，不会用旧响应覆盖新修改。单文件通过 GitHub Contents API 的 PUT 与文件 SHA 比较更新，保留仓库其他文件；返回成功后读取新提交的实际内容核对。冲突、网络中断或结果不明时停止自动重发，显示重试入口并保留本机草稿。

这是一套适合少量小说管理的文件数据同步方式，不提供即时推送或多人同时编辑同一条记录的无冲突数据库事务。正文生成、GPT 定时任务、小说平台发布均仍是独立操作。

## 1.2版更新查询

在“我的小说”勾选后点击“查询今天更新”，或打开“今日更新”点击同名按钮。不限制时间，不依赖计划或完成回执，按北京时间的最新章节文件提交日期判断。正常公开读取不调用GitHub REST接口。读取失败单独列出，不计为今天未更新；读取无需凭证或GPT API Key。保存查询记录沿用已有自动同步授权。详见《今日更新查询.md》。

## 1.2.1版：直接生成日更指令

首页标题旁直接显示“生成日更指令”，导航第二项是“日更指令”；每本小说操作里也有同名入口，原“更多 → 定时指令”仍可进入。手机上不用把小说表格横向滑到最右边寻找菜单。

在独立页面选择已加入的小说、设置每天北京时间，点击“生成并复制指令”。完整内容自动带入当前小说仓库、分支、选定时间、管理仓库和原每日一章流程，并在下方保留预览。切换小说时更新书名、仓库和默认时间，复制时重新按当前选择生成，避免复制前一本书的指令。可选“打开本书GPT聊天”使用清单中的链接；未填写时说明从编辑处添加，也可以自行打开聊天粘贴。

生成指令本身不修改清单或已建立的GPT计划。作者发送到本书工作聊天后，由GPT实际创建任务；需看到任务卡片与下次执行时间。复制失败时仍保留完整预览，可长按复制。
